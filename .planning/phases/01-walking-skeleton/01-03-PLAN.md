## Phase Goal

**As a** GSD project owner, **I want to** install the Memanto capability once globally, enable it in one project, and watch a real discuss-phase run pass or halt on a Memanto gate, **so that** a misconfigured or unhealthy Memanto blocks the workflow instead of silently failing open.

<objective>
Make the gate resolve the same `memanto.*` and `mempalace.enabled` values gsd-core resolves (D-05), including GSD_PROJECT and GSD_WORKSTREAM directories, and pin that parity with a contract test against the real `gsd_run config-get` and `loop render-hooks`.

Purpose: an owner using workstreams or project scoping gets a gate that checks the configuration gsd-core actually activates, so the gate can never check one config while the host activates another (CONF-01, CONF-02, CONF-03).
Output: host-parity lib/config.cjs, unit tests, contract test.
</objective>

<feature>
  <name>Gate config resolution matches gsd-core</name>
  <files>lib/config.cjs, test/config.test.cjs, test/config-contract.test.cjs</files>
  <behavior>
    Cases (input → expected):
    - no .planning/config.json → memanto.enabled false, agent_id "", backend_url "", api_url "" (manifest defaults); mempalace.enabled undefined
    - root {memanto:{agent_id:"a"}} → "a"
    - GSD_WORKSTREAM=w, only workstreams/w/config.json {memanto:{agent_id:"w"}} → "w"
    - both files, workstream {memanto:{agent_id:"w"}}, root {memanto:{agent_id:"r"}} → "w"; a key present only in root → root value
    - GSD_PROJECT=p → files under .planning/p/
    - {memanto:{enabled:"false"}} → "false" (string, so not activating)
    - malformed root JSON → ok false with that path
    - {"__proto__":{"memanto":{"agent_id":"x"}}} or key path containing constructor → absent (default)
    - GSD_WORKSTREAM "../x" or "a/b" → ok false
    - $GSD_HOME/.gsd/defaults.json {memanto:{agent_id:"d",enabled:true}} → ignored
  </behavior>
  <implementation>planningDirs builds the scoped directory from env GSD_PROJECT then GSD_WORKSTREAM, rejecting names that contain '/', '\\' or '..'. resolveConfig reads scoped config.json then root config.json (when the paths differ), each optional, and stops at the first own-property hit before the manifest default. Malformed JSON in either file returns ok false (fail closed, documented divergence from the host).</implementation>
</feature>
