## Phase Goal

**As a** GSD project owner, **I want to** install the Memanto capability once globally, enable it in one project, and watch a real discuss-phase run pass or halt on a Memanto gate, **so that** a misconfigured or unhealthy Memanto blocks the workflow instead of silently failing open.

(Sourced from the ROADMAP Phase 1 Goal and the PROJECT core value. The ROADMAP `**Goal:**` line is prose, not user-story form; `/gsd-mvp-phase 1` would rewrite it if a canonical story is wanted.)

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo config → gate | `.planning/config.json` is repo content (a cloned repo controls it) and is read by the gate process |
| host → gate process | gsd-core runs the manifest command through `sh -c` at the project root |
| dev script → owner home | tools/stage-bundle.cjs can install into the real GSD home |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering / Elevation | capability.json gate command | high | mitigate | Static command string with `${GSD_HOME:-$HOME}`; no config value is interpolated into `sh -c`; the gate reads config in-process (lib/config.cjs) |
| T-01-02 | Elevation (fail-open) | scripts/gate.cjs, lib/checks.cjs | high | mitigate | Top-level catch writes `[gate-internal]` and exits 1; unreadable config returns the `config-unreadable` error; a missing gate script makes node exit non-zero, which the host treats as block |

| T-01-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installs in this plan; zero runtime and dev dependencies; package-legitimacy gate + blocking human checkpoint for [ASSUMED]/[SUS] packages applies wherever an install appears (plan 01-08) |
